- [x] Ability to keep one AI answer per post and content: `012-post-tags` adds `harvest_post_tags`, keyed by

- [x] Ability to receive done tags as a new post revision with `post.changed`: tier `SmallModel`, `type:`, `domain:`

### Iteration 11 — AI extraction (app-t-010 step B)

- [x] Ability to extract only what a subscriber wants: `Harvest:Processing:Extraction:Wanted` names `{ entityType,
  domain }` pairs (`event` + `style-fashion` for Ocharo, `listing` + `real-estate` for Haven); a post qualifies when its
  done `post-tags` answer has the type and a node at or under the key; `IPostExtractionDemand` is the seam the
  selector (S09) implements later
- [x] Ability to queue extraction after tagging finishes and again once a changed text's new tags are done, in the
  write's transaction, keyed by the same title-and-text hash; `extract backfill` queues stored posts for a new pair
- [x] Ability to keep one answer per post, content and use case: `013-post-extractions` adds `harvest_post_extractions`
  (prompt version and hash, inference, model, role, validated `answer`, `flags`, `status`, `attempts`, timestamps) and
  the `extract-event` / `extract-listing` kinds of `harvest_post_work`; the post's `base` is never written
- [x] Ability to parse an event post with `extract-event`: name without year or ordinal (English and original),
  edition label, occurrences with precision and certainty, place, organizer, format, access, prices, registration,
  participation, status, relation (role, changes, new status) and a `fashion` block under `style-fashion`
- [x] Ability to parse a listing post with `extract-listing`: title, offer type, the source's category path, price with
  period, location, identity hints, author kind with no names or contacts, relation, and `rental-terms@2`'s terms for a
  real-estate rent
- [x] Ability to keep only evidence-backed values: every date, price and rental term carries a verbatim quote from the
  title or the text the model read, checked as `rental-terms@2` checks it (now shared from `PostExtraction/`); a failing
  value becomes unknown with a flag, the rest stays
- [x] Ability to flag every unsure pick and removed contact, counted by proposed value in the report
- [x] Ability to register both prompts and run, backfill and report extraction with the `extract` host verb; prompts
  live in the AI database, schemas in code
- [x] Run the backend suite → 1,199 pass, 0 warnings: Unit 316, Integration 105, E2E 66, Conformance 213,
  Migrations 10 (the be sdk migration lint covers `013`), HarvestAdapters Unit 404, HarvestAdapters Integration 19,
  HarvestSources E2E 66
- [ ] Register the `extract-event` and `extract-listing` prompts on dev and run a labeled sample → accuracy, flags,
  cost and latency recorded

### Iteration 12 — Entities (app-t-010 step C)

- [x] Ability to keep one record per real-world thing: `014-entities` adds `harvest_entities` (type, canonical English
  name, `name_key`, aliases and their keys, primary domain, merged `facts`, status, cadence and its confidence, first
  and last seen, `merged_into`), `harvest_entity_occurrences` (label, dates, precision, certainty, `predicted`, status,
  place, `history`), `harvest_entity_relations` (post, content, use case, entity, occurrence, role, changes, `offer`,
  confidence; one row per post and entity), `harvest_entity_keep_apart`, `harvest_entity_flags` and the
  `entity-resolve` kind of `harvest_post_work`
- [x] Ability to queue a post's resolution when its done extraction lands, in the same transaction, while
  `Harvest:Entities:Enabled` is set (off by default); `entities backfill` queues stored answers
- [x] Ability to match one name across languages: Russian, Uzbek Latin, Uzbek Cyrillic and English forms share one
  `name_key` with years and ordinals stripped; other names match by pg_trgm similarity of names and aliases
- [x] Ability to bind event posts with their role: candidates share the container and a similar name, a known
  different city or domain rules one out, an edition matches on dates within ±10 days or the label's year;
  `announcement` creates or confirms, `update` moves status and dates with history (an estimate never overrides a
  stated date), `report` marks held, `mention` only attaches
- [x] Ability to infer cadence and predict: two or more stated starts give annual, semiannual, quarterly, monthly or
  irregular with a confidence and configurable tolerances; one predicted occurrence follows the last real one and is
  replaced when a real one arrives
- [x] Ability to deduplicate listings across authors and sites: the same `(source_id, external_key)` or the same
  author's ad is an `update`; another author's ad matching district, rooms, area within 5%, offer type, price band and
  category path is another `announcement` with its own offer; `facts.priceSpread` keeps each author's latest price
- [x] Ability to flag instead of merging: a match below `Harvest:Entities:MinMatchConfidence` or too close to another
  binds nothing and records an unsure flag with its candidate
- [x] Ability to read and correct entities with the `entities` host verb: `resolve`, `backfill`, `show`, `search`,
  `merge`, `split` (keep-apart, honoured by merge and resolution) and `report`; no post text in any output
- [x] Run the backend suite → 1,269 pass, 0 warnings: Unit 374, Integration 113, E2E 66, Conformance 213,
  Migrations 11 (the be sdk migration lint covers `014`), HarvestAdapters Unit 404, HarvestAdapters Integration 19,
  HarvestSources E2E 69
- [ ] Enable entities on dev, backfill, and review `entities report` and its flags → counts and flags recorded
