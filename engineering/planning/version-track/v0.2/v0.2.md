### Iteration 1 — The merge

- The source readers came over from `harvest-adapters` as its current tree, without its git history.
  - A gitleaks scan and a grep of all 31 commits found no credential, token, host or address.
  - History did hold a person's first name in the Ocharo registry, so the history stayed in the old repo, which stays
    private. The name is removed in this copy.
  - The scan also flagged a public organizer phone in the test fixtures; it was already in this repo's own fixtures.
- Layout (`engineering/codebase/harvest.backend-services/`):
  - `sources/` holds the readers and their composition (`Afisha`, `Anons`, `Caex`, `Craftfair`, `Instagram`,
    `Integrations`, `Module`, `Olx`, `Uzexpocentre`). They are not packable and get the same strictness as the NuGet
    family.
  - `service/HarvestSources.Api` is the one deployed host. `service/Harvest.Api` stays as the generic host the E2E
    and conformance tiers run.
  - The readers' tests sit beside the engine's: `tests/HarvestAdapters.Tests.{Unit,Integration}`,
    `tests/HarvestSources.Tests.E2E`. There is one solution, `SCFD.BackendServices.slnx`.
- Dropped, since they existed only for two repos: `harvest-runtime.json` and its `publicHarvestRef`, the
  `HarvestSourceRoot` and `HarvestSdkVersion` switches with their build target, `verify.py`, the image build that
  downloaded this repo by pin, the readers' empty frontend folder, and the second set of workflows and docs.
- Deployment:
  - one `Dockerfile` that builds `HarvestSources.Api` from this tree
  - one `deploy.yml` (product `harvest`) with every setting the source host reads
  - one `docker-compose.yml` with an `.env.example`
- A new advisory, GHSA-wr8v-9x5q-ggcm, hit `Microsoft.AspNetCore.SignalR.StackExchangeRedis` 10.0.3, which comes in
  through be sdk `10.0.111-beta`. It is pinned to 10.0.15 transitively until the be sdk ships the fix.
- Also in this iteration:
  - `GET api/sources/{id}/posts` gains `endsAt`, the event end as stated. The console marks a post `ongoing` from its
    start to its stated end, and `finished` after it; with no stated end it says neither (console live edits,
    2026-11-11).
  - `ContainersPanel`, which the console rebuild left unused, leaves fe-harvest's `./admin`.
  - The scheduled `conformance` run, red since 2026-11-12 on the same advisory, runs green against the merged image
    locally: 41 client conformance tests.

### Iteration 2 — One host

The generic host `service/Harvest.Api` is gone; nothing shipped it after the merge. `HarvestSources.Api` is the one
host, which the image runs and the E2E and Conformance tiers boot.
- References removed: the solution, the E2E and Conformance test projects (now on `HarvestSources.Api`), the ignore
  rules for the host's `wwwroot`, and the docs. Hosting keeps its `Harvest.Api.*` namespaces.
- One E2E case moved: an unread source reports `unavailable` for `youtube`, since the source host registers a reader
  for Instagram.
- Verification on 2026-11-13 with SDK 10.0.404: the solution builds with 0 warnings. 729 backend tests pass (188 engine
  unit, 55 integration, 198 conformance, 6 migration, 57 E2E; 206 reader unit, 3 reader integration, 16 source-host
  E2E), and the contract pages are unchanged.
- [x] Release `v0.2.1` (run 43288854437); the conformance run on the released image passes
