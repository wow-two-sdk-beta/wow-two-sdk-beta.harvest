### Iteration 3 — Haven's marketplace setup

Haven restart goal (wow-two-ws `system/sessions/haven-restart/haven-restart.md` #2): SCFD collects OLX listings for
Haven into a private container and delivers them through `wow2.post.v1` subscriptions Haven Supply pulls.
- Product-neutral marketplace setup: a profile is data (`MarketplaceProfile`, `MarketplaceProfiles`), and
  `MarketplaceProvisioner` applies any profile idempotently: tenant, private container, the OLX source, one pipeline and
  one subscription per saved search, and the consumer's key. Host verb `marketplace setup|status --profile <key>` and
  operator routes `api/marketplace/profiles`, `api/marketplace/{profile}/setup|status`.
- Profile `haven`: tenant `haven`, container `haven-listings`, three Tashkent searches read newest first — apartments
  and houses for long-term rent and daily rent (slugs from OLX's own category tree, 2026-11-14). Haven v1.0 read every
  Tashkent apartment and ListingShelf the same category; rent-only categories leave sales out.
- Filter `marketplace-listing-v1` passes listings only. Capture every 2 h and a daily check, off until `--schedules`.
- Run budget: a run's page count includes every ad it reads, so `maxPages: 2` would capture a single ad (found by the
  host test); the profile reads at most 60 ads with 64 pages.
- Credential: a tenant API key `haven-supply` with `events:read` only, issued by `--issue-key`, its secret shown once on
  stdout. Picked over an OAuth client, which needs an Identity release of the issuer and a `ClientGrantsJson`
