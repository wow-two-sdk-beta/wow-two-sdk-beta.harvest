### Iteration 12 — Service access, browser sign-in and the SCFD brand

`d77daf6` replaced API-key console access with scoped service access: an Identity issuer's audience-bound
`client_credentials` tokens, mapped to an operator or a tenant by `Harvest:ServiceAccess:ClientGrantsJson`.
Browser sign-in returns beside it: an Identity authorization-code BFF that binds a person's organization to one
SCFD tenant, with `harvest:` organization permissions and named operator subjects. Subscriptions accept
`tag:<value>` filters (`DeliveryTagFilter`). A pipeline scope can keep its work under the starting URL's path, and the
console's source picker offers those sections. The product, solution and console carry the SCFD brand; the product id
stays `harvest`.

### Iteration 13 — Events consumer contract

For the Events integration (wow-two-ws `system/sessions/events-integration`, #15–#19). Identity scopes are
`harvest.{noun}-{verb}` under the `harvest` resource, so `events:read` is granted by `harvest.events-read` and no
longer by `events.read`. The Client sends a client-credentials token from `HarvestClientOptions.Identity` on every
broker, through the be sdk's `Http.Auth`. `wow2.event.v1` fills `organizer` only from a declared organizer, adds
`postedAt` and a `mapping` stamp (`rules@4`), and carries the newest `capture`; each pulled `DeliveryEvent` names its
`pipelineId`. Pins: be sdk `10.0.111-beta`, Identity `10.0.30-beta`, whose API keys gain six check characters.

Verification on 2026-11-10 with SDK 10.0.403: 442 backend tests pass (176 unit, 52 integration, 162 conformance,
5 migration, 47 E2E); frontend type checks, tests and format check pass. Under a load average near 220 one robots
rule test timed out in its regex and passed alone. No deployed target was checked.

The dev Afisha sample (adapters `v0.1.4`, 2026-11-10) delivered one fashion event with dates, place, geo, offer,
`postedAt` and the mapping stamp, but its `place` and `postedAt` enums travelled as numbers. The mapper now writes
camelCase string enums, and a stored projection carrying the stamp renders again through the current mapper; a
reader's own projection is sent as stored. 442 backend tests pass.

- [x] Ability to pull a `wow2.event.v1` record on dev with Events' `harvest.events-read` token
- [x] Ability to refuse that token on operator routes and on another tenant's subscription

Dev evidence (events-integration Status, 2026-11-10): Events' intake pulled the Afisha record with its own token and
published it; the cross-lane review found operator routes answering `403` and the isolation tenant's subscription
answering `404` for that token.

### Iteration 14 — Classification shape and lifecycle types

`PostEnvelope.Classification` (`PostClassification`: `classifier`, `verdict` relevant, irrelevant or uncertain,
`confidence` 0 to 1, `reason`, `kind`) is the object Events' `payload` classifier reads (events-integration #53, #55).
`wow2.event.v1` carries it as `classification` and its kind as a top-level `kind`; both stay null until the model tier
writes them, so sourced events still map to kind `other`. `post.purged` stays a reserved type: no step emits it until
the retention purge (#33) ships, and consumers keep honouring it. The backlog drops the rows v0.1.11 shipped.
Verification on 2026-11-10 with SDK 10.0.403: 443 backend tests pass (177 unit, 52 integration, 162 conformance,
5 migration, 47 E2E).

### Iteration 15 — `wow2.event.v1` contract pages

`tests/Contract/wow2.event.v1/` holds golden pull pages that Events replays (events-integration #43, the shape agreed
with Events on 2026-11-10): `subscription.json`, `01-new`, `03-changed`, `04-empty` (the cursor comes back),
`05-lifecycle`, `06-classification`, `07-afisha-place` (the live Afisha location before and after the city fix) and
`08-purged`, with a `manifest.json` of sha256 and cases. The E2E tier's `EventContractPagesTests` serves them from the
real host with a fixed clock and renumbered Guids; `HARVEST_WRITE_CONTRACT=1` rewrites them, and otherwise the test
fails on the first differing byte. Writing them found a resolve bug: a declared schema.org organizer reached the wire
as `null`, because post resolution dropped its `organizer` field source; it now travels with the chosen author.
`post.relisted`, `pipeline.run` and `pipeline.health` are marked reserved like `post.purged`: no step emits them, and a
relist reaches subscribers as `link.state` relisted. Verification on 2026-11-10 with SDK 10.0.403: 444 backend tests
pass (177 unit, 52 integration, 162 conformance, 5 migration, 48 E2E).

### Iteration 16 — Console layout, iteration 1

The developer confirmed the console's page separation (events-integration #56, #58) and asked for Wheelhouse's
layout. The 1,283-line `HarvestConsolePanel` is split into one `./admin` panel per page under
`HarvestConsoleProvider`. `apps/web` has a route per page: Home; Sources, Pipelines, `/pipelines/:id`, Runs; Posts;
Subscriptions; Hosts, Access. They share one `AppLayout` on the fe sdk shell: a 56 px bar with the collapse toggle
(persisted), breadcrumb, container switch and the SDK `AccountMenu`, hairline borders, and light and dark through
`ColorModeProvider` with a pre-paint script. Sources is a read-only catalog of what the adapters registered, and a new
pipeline is created by choosing a source and one of its sections, never by typing a URL. The console client now
addresses `/api/` from the origin root, since nested pages had sent `api/…` relative to their own path. The API is
unchanged. Verification on 2026-11-10: lint, type check, format check and build pass, with 28 fe-harvest and 21 web
tests. Every route loads on the local preview signed in as an operator, with screenshots in light and dark.

### Iteration 17 — Console: Sources from the mocks

Built from the developer's saved mocks (wow-two-ws `system/sessions/events-integration/scfd-console/`, points
#30–#45, `mocks/iter-1/`).
- Store and API: migration `006-source-groups` adds named source groups, a source's display name and group, and
  `harvest_post_revisions`, written by the post resolve on every create and revision rise with the fields that
  changed. `ISourceOverviewBroker` serves a source's overview, its posts and a post's revisions, and
  `IRunBroker.SetReadingPaceAsync` sets a host's pace.
  - The overview carries the last harvest's new and found counts and result, the next harvest, a 14-day series of
    new posts, each section's cadence, page limit, last run, posts and subscribers, and the host's health.
